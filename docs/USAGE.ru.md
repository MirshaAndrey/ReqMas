# Использование Reqmas

## Возможности

- GET / POST / PUT / PATCH / DELETE / HEAD / OPTIONS.
- Query parameters и headers: добавление, удаление, включение и выключение строк. Query parameters синхронизируются со строкой URL в обе стороны; выключенные параметры сохраняются в таблице и не отправляются.
- Body: none, JSON с подсветкой, форматированием и проверкой, raw text, XML, URL encoded, multipart, binary. GET/HEAD отправляются без body.
- Response: status, время, размер body, Pretty / Raw / Tree / Headers / Compare, подсветка, поиск, копирование и сохранение исходного файла. Растровые изображения показываются в preview.
- Коллекции с деревом вложенных папок, сохранённые запросы, поиск и история последних 100 успешных HTTP обменов (включая 4xx/5xx).
- Независимые вкладки с черновиками, ответами, поиском и настройками редактора.
- Импорт cURL и копирование запроса как cURL с подставленными переменными и авторизацией.
- Отмена запроса, таймаут 0.1–300 секунд (по умолчанию 30) и настройка redirect.
- Сохранённые сценарии Runner с CSV/JSON данными и повтором неуспешных запросов.
- OAuth 2.0 Client Credentials, Authorization Code + PKCE и автоматическое обновление токенов.
- Desktop: SQLite, системная защита структурированных секретов, автоматические резервные копии, HTTP(S) proxy, собственные CA и mTLS, настройка подписанных обновлений.
- Демо-запросы к JSONPlaceholder.

В браузере рабочее пространство сохраняется в localStorage. В desktop коллекции, запросы, окружения, cookies, история, сценарии, черновики и настройки сохраняются в SQLite: `workspace.sqlite3` в каталоге приложения, который возвращает Tauri `app_data_dir` (обычно `%APPDATA%\com.reqdesk.desktop` в Windows). Размер сохранённого документа workspace ограничен 50 MiB. При первом запуске новой desktop-версии старые данные WebView переносятся в SQLite; принадлежащие Reqmas записи localStorage удаляются только после успешного сохранения. Ошибка загрузки или переноса показывает экран с Retry до открытия рабочего пространства.

Для совместимости с данными прежней версии Reqmas сохраняет служебный desktop identifier `com.reqdesk.desktop`, префикс хранилища `reqdesk.` и поле дополнительных данных `reqdesk` в экспортах коллекций.

С версии 0.2.1 один desktop workspace редактируется одной копией приложения. Вторая копия показывает сообщение о занятом workspace до открытия данных. Закройте первую копию и перезапустите вторую. Блокировка освобождается операционной системой при завершении процесса; оставшийся файл `workspace.sqlite3.lock` удалять не нужно. Более старые EXE не поддерживают эту защиту: закройте их перед переходом на новую версию.

В Windows DPAPI, а в macOS и Linux AES-256-GCM с ключом в системном Keychain / Secret Service защищают значения с отметкой **Secret**, сохранённые пароли Basic/proxy, Bearer/API key/OAuth credentials, cookies и приватные ключи mTLS в desktop-базе и новых автоматических копиях. Защита привязана к учётной записи ОС и её системному хранилищу ключей; файл SQLite нельзя использовать для переноса credentials на другой ПК. Остальные данные остаются обычными: raw body, datasets, вложения и произвольные поля могут содержать введённые вручную секреты. Браузерные данные и JSON-экспорты не шифруются. Это не полное шифрование workspace; удаление старых записей не гарантирует удаления их следов из кэшей или ранее созданных файлов/копий базы. Для переноса используйте JSON backup с явно включённым **Include secrets**.

Облачная синхронизация отсутствует.
В браузере действуют CORS и ограничения на некоторые headers; в desktop HTTP выполняется Rust/reqwest через IPC.
Размер response — размер полученного body, не полный размер сетевого обмена. Максимум body ответа — 100 MiB в обоих transport; превышение прерывает скачивание с ошибкой.
Новые записи истории сохраняют status, headers, body и снимок запроса. Выбор записи открывает ответ в отдельной вкладке без повторной отправки. Старые записи содержат только запрос. Body ограничен 100 KiB на запись и 1 MiB на всю историю; усечённые ответы отмечены в интерфейсе. Полный ответ остаётся в исходной вкладке до её закрытия или перезапуска.

## Код

- `src/App.tsx` — рабочее пространство.
- `src/types/request.ts` — типы данных.
- `src/services/httpClient.ts` — браузерный и desktop transport.
- `src/storage/database.ts`, `src/storage/desktopStore.ts` — локальное сохранение, миграция и очередь записи.
- `src-tauri/src/main.rs` — HTTP backend и отмена запросов.
- `src-tauri/src/workspace_store.rs` — SQLite, защита секретов и автоматические копии; `src-tauri/src/updates.rs` — подписанные обновления.

## Импорт коллекций Postman

1. Экспортируйте коллекцию из Postman в JSON Collection v2 или v2.1.
2. Нажмите **Import from Postman** в левой панели.
3. Выберите `.postman_collection.json` или вставьте содержимое JSON.
4. Проверьте preview: число запросов, переменные, пропущенные элементы и предупреждения.
5. Нажмите **Import collection**. Будет создана отдельная коллекция; существующие данные не заменяются.

Поддерживаются вложенные папки (отдельное поле folder и список папок коллекции), URL и query, enabled/disabled headers и параметры, raw JSON/text body, collection/folder/path variables, Bearer Token, Basic Auth и API key. GET, POST, PUT, PATCH, DELETE, HEAD и OPTIONS доступны в обоих transport.
Переменные коллекции редактируются через ⚙ рядом с названием, локальные переменные запроса — через вкладку **Variables**. Запрос с неопределённой переменной не отправляется и показывает имя отсутствующей переменной.
Bearer, API key, Basic и OAuth доступны во вкладке **Auth**. Запросы могут наследовать авторизацию коллекции или переопределять её; None отключает наследование и оставляет явно заданные headers.

Postman scripts и тесты не выполняются. Поддерживаются multipart/form-data, binary, urlencoded и XML. Обычный экспорт Postman содержит пути файлов: их нужно прикрепить заново. GraphQL body и неподдерживаемые виды авторизации пропускаются с предупреждением. OAuth 2.0 импортируется с токеном или настройками для Client Credentials. Экспорт environments и workspace dumps не являются collection-файлами и отклоняются.

Лимит collection-файла — 50 MiB вместе с embedded files, 10 000 запросов и папок суммарно, 100 уровней папок. Превышение проверяется до рекурсивного импорта. Повреждённое embedded-вложение не принимается как рабочий файл; некорректный header пропускает соответствующий запрос с предупреждением.

Описание исходного формата: https://schema.postman.com/collection/json/v2.1.0/draft-07/docs/index.html

## Импорт OpenAPI / Swagger

Нажмите **Import OpenAPI / Swagger** в левой панели, выберите файл JSON/YAML или вставьте спецификацию, затем **Preview import → Import collection**. Поддерживаются Swagger 2.0 и OpenAPI 3.0/3.1. Импорт создаёт новую коллекцию с папками по tags, URL, path/query/header параметрами, примерами body, переменными и Basic/Bearer/API key auth. JSON Schema первого подходящего успешного JSON ответа автоматически переносится во вкладку **Schema** запроса.

Preview показывает запросы, число схем, пропуски и предупреждения. Необязательные параметры без example/default выключены. При нескольких servers/media/security вариантах импортёр выбирает один и предупреждает; перед отправкой проверьте примеры и auth. Файлы multipart/binary прикрепляются вручную. OAuth flows, callbacks/webhooks и произвольная сериализация сложных параметров не импортируются полностью.

Спецификация должна быть самодостаточной: `$ref` поддерживает ссылки внутри документа, внешние URL и файлы не загружаются. Максимум — 2 MiB и 2 000 операций. **Fallback base URL** используется для отсутствующих или относительных адресов servers; абсолютный server сохраняется.

## Управление запросами

- **New request** / + рядом с коллекцией: имя, коллекция, метод, URL → **Create request**. Запрос сразу сохраняется.
- Выберите запрос: измените имя, URL, метод, Params/Headers/Body/Auth/Variables → **Save request**.
- Перетаскивайте запрос на папку или корень коллекции для переноса, на другой запрос — для вставки перед ним. Коллекции тоже можно переставлять перетаскиванием.
- Кнопка **⋯** рядом с запросом открывает **Move up / Move down**, выбор Collection/Folder и **Move request**; у коллекции она меняет порядок. Все эти действия доступны с клавиатуры. Для переноса из редактора также можно выбрать другую **Collection / Folder** над URL и сохранить запрос.
- **Duplicate** создаёт независимую сохранённую копию.
- **Delete** / × в списке: диалог подтверждения, затем удаление из коллекции.
- **Restore deleted** в нижней строке восстанавливает удалённые сохранённые запросы/коллекции. Корзина сохраняется локально и переживает перезапуск. История запросов при удалении сохраняется.
- Переключение вкладок сохраняет черновики и ответы. При закрытии несохранённой вкладки доступны **Save and close**, **Discard and close** и **Cancel**. Черновики переживают перезапуск; ответы доступны в истории.

Коллекции и вложенные папки раскрываются стрелкой; их состояние сохраняется. Поиск временно раскрывает совпадения, после очистки возвращает выбранное состояние дерева. **Ctrl+K** переводит фокус в поиск, **Ctrl+Enter** отправляет запрос, **Ctrl+S** сохраняет его. Горячие клавиши приостановлены при открытом диалоге.

Проверка импортёра и подстановки переменных: `npm test`.
Тестовый файл коллекции: `tests/fixtures/demo.postman_collection.json`.


## Окружения и экспорт

**Workspace → Environments**: создание, редактирование, дублирование, удаление, импорт и экспорт Postman environment JSON. Изменения применяются по **Save workspace**, Cancel их отменяет. Активное окружение выбирается сверху. Приоритет переменных: collection < environment < request. Значения подставляются в URL, params, headers, body, form fields и auth; отсутствие переменной или цикл блокирует отправку.

Импорт environment ограничен 1 MiB и 10 000 переменными. Ключи должны быть строками; значения — строками, конечными числами, boolean или null. Вложенные объекты/массивы и некорректные записи отклоняются с понятной ошибкой.

**Workspace → Export** выгружает сохранённые коллекции как Postman v2.1. Папки, переменные, auth и типы body сохраняются. Файлы, декларативные проверки и схема ответа дополнительно встраиваются в поле reqdesk для импорта обратно в Reqmas; Postman не исполняет эти проверки и требует повторного прикрепления файлов.

Экспорт коллекций, environments и workspace по умолчанию исключает значения, отмеченные **Secret**, и известные поля credentials; ссылки вида `{{token}}` сохраняются. Для передачи сохранённых credentials явно включите **Include secrets** перед экспортом. Это обычный JSON с открытыми значениями. Raw body, datasets и файлы не проходят универсальную проверку содержимого: секреты, введённые вручную в такие данные или произвольные поля, могут попасть в экспорт и без этой отметки.

## Папки и body

Настройки коллекции позволяют создавать вложенные пути, переименовывать и удалять папки. Родительские папки отображаются в дереве, даже если явно создан только вложенный путь. При удалении папки запросы перемещаются в корень. Изменения применяются вместе с Save collection. Для переноса запроса выберите Folder и Save request либо используйте дерево и кнопку ⋯.

Body поддерживает JSON, text, XML, URL encoded, multipart с текстовыми полями и файлами, binary. Ограничение одного вложения — 10 MB. Байты файла сохраняются локально; GET/HEAD body не отправляют. Multipart Content-Type и boundary формируются автоматически.

## Проверки и Runner

Вкладка Tests: status equals, time ≤ ms, body contains, header equals, JSON path equals. JSON path использует точки и индексы массива, например users.0.id. В строковых значениях не нужны кавычки, остальные значения задаются как JSON. Результаты фиксируются для отправленного запроса.

Runner запускает выбранные сохранённые запросы последовательно, от 1 до 100 итераций, с паузой и остановкой по первой ошибке. Запросы выполняются с активным окружением, авторизацией коллекции и собственным таймаутом из Settings. Stop run отменяет текущий запрос. HTTP 4xx/5xx, неуспешные проверки и правила Capture считаются ошибками. Отчёт можно выгрузить в JSON. Выполненные запросы с ответами добавляются в историю.

**Saved scenario** сохраняет выбор и порядок запросов, итерации, паузу, остановку по ошибке и CSV/JSON данные. Введите **Scenario name** и нажмите **Save scenario**; доступны изменение, **Save as new scenario**, удаление и отмена удаления, пока Runner открыт. Можно сохранить до 100 сценариев; они входят в workspace backup. Сценарий с удалёнными или перенесёнными в другую коллекцию запросами показывает недоступные элементы: удалите их из выбора или восстановите запросы перед запуском. Один запуск ограничен 10 000 выполнениями запросов.

**Runner → Iteration data** принимает CSV или JSON из файла либо вставки. Каждая строка запускает выбранные запросы один раз; число строк определяет Iterations. Имена CSV столбцов или JSON ключей становятся переменными, например `{{caseId}}`. Приоритет: collection < environment < dataset < request. Данные не изменяют сохранённые переменные и сохраняются между открытиями Runner только вместе со сценарием. CSV поддерживает quoted commas, doubled quotes и многострочные ячейки. JSON — массив объектов со строками, числами, boolean или null; отсутствующий ключ сохраняет значение окружения, пустая строка его переопределяет. Лимит — 100 строк, 100 столбцов и 1 MiB. Preview показывает первые пять строк; результаты содержат номер строки данных.

Числовые значения JSON dataset сохраняются точно при переносе в переменные, включая большие ID, дроби, экспоненты и `-0`; округление через JavaScript Number не выполняется.

**Retry failed** повторяет только завершившиеся ошибкой задачи, используя снимки исходных запросов и исходные строки dataset с теми же номерами итераций. Отменённые и ещё не выполненные запросы исключаются; результат заменяется и увеличивается номер попытки. Окружение и наследуемая авторизация коллекции берутся из текущего workspace, а пауза и остановка по ошибке — из текущих настроек Runner. Значения, записанные Capture, доступны следующим запросам и повторным попыткам. Это не снимок всего окружения на момент первого запуска. Отчёт и возможность повтора доступны до закрытия окна Runner.

Вкладка **Schema**: задайте JSON Schema, отформатируйте её или нажмите **Generate from response**, чтобы получить стартовую схему текущего JSON. **Check current response** проверяет уже полученный ответ; при Send и в Runner схема проверяется автоматически. Пустое поле выключает проверку. Для Runner сохраните изменения через **Save request**. Ошибки показывают путь JSON и причину.

Поддерживаются draft-07 по умолчанию и явный draft 2020-12, локальные `$ref`, types, required, enum, formats и составные проверки. Валидация работает локально без `eval` и изменения ответа. Удалённые ссылки, `$dynamicRef`/`$dynamicAnchor` и смешение диалектов отклоняются явно. Максимум схемы — 1 MiB. Генерация по одному ответу даёт пример, который нужно уточнить под контракт API.

Schema validator использует числовую арифметику JavaScript. Если schema или ответ содержит число, которое нельзя передать в неё без потери точности, проверка явно сообщает об этом и не выдаёт округлённое значение за успешную проверку. Pretty, Tree, Compare, JSON path assertions, Copy, Capture и JSON datasets при этом сохраняют точные числовые значения.

## OAuth и cookies

Auth: Basic, Bearer, API key в header/query и OAuth 2.0 **Client Credentials / Authorization Code + PKCE**. Credentials для token endpoint передаются в body или Basic header. Авторизацию коллекции задают через ⚙ рядом с её названием; у запроса по умолчанию Inherit from collection. Можно вставить существующий токен или использовать переменную окружения.

Для **Authorization Code + PKCE** заполните Authorization URL, Token URL, Client ID и Redirect URI, затем нажмите **Get token**. Desktop открывает системный браузер; используются S256 и проверка state, callback принимается через локальный listener. Зарегистрируйте у провайдера точный Redirect URI, по умолчанию `http://127.0.0.1:58809/oauth/callback`. Допускается `http://127.0.0.1:PORT/path` с фиксированным портом и без query. Для публичного клиента Client Secret необязателен. Authorization/Token URL требуют HTTPS; HTTP разрешён только для localhost при тестировании.

**Refresh an expired token before sending** включает обновление до отправки запроса, в том числе в Runner: используется refresh token, а для Client Credentials без него запрашивается новый access token. Если для Authorization Code отсутствует пригодный refresh token, потребуется снова **Get token**. Одновременные обновления одного OAuth account выполняются последовательно. Browser mode поддерживает вставленные токены, Client Credentials и refresh при разрешённом CORS; интерактивная авторизация PKCE требует desktop. OAuth 1.0 не поддерживается.

Desktop cookies управляются через Workspace → Cookies. Все Set-Cookie конечного ответа сохраняются с path, expiry и secure; полученные cookies привязаны к отвечающему host. Sharing на поддомены включается вручную в редакторе cookie. Cookies промежуточных redirect-ответов пока не сохраняются. Cookie header, заданный в запросе, имеет приоритет над jar. Browser mode использует браузерный cookie store; cross-origin cookies включаются в Auth и требуют credentialed CORS. Browser APIs не показывают Set-Cookie.

В Response добавлен регистронезависимый поиск по строкам, подсветка найденных строк и переходы вперед/назад в Pretty/Raw/Headers.

**Tree** раскрывает JSON объекты и массивы, копирует значение узла и путь JSON Pointer; узлы после первой тысячи доступны на следующих страницах. **Compare** сравнивает body с ответом другой вкладки или историей, показывает добавленные/удалённые/изменённые значения по путям; порядок ключей объекта не считается изменением. Усечённая история не используется для сравнения. На странице Tree показывается до 1 000 узлов; JSON для Tree/форматирования ограничен 2 MB. Diff ограничен 200 различиями и 10 000 JSON узлами; интерфейс сообщает об ограничении. Большие числовые ID и точные дроби не округляются при отображении, сравнении и копировании.

**Save response** сохраняет исходные байты, включая бинарные файлы и исходную кодировку текста. Имя берётся из Content-Disposition или URL и очищается от недопустимых символов. Pretty показывает raster image preview; HTML/SVG не выполняются. В browser mode сервер должен открыть Content-Disposition через CORS, чтобы имя файла было доступно. Усечённый ответ истории нельзя сохранить как полный файл — отправьте запрос снова. Бюджет истории учитывает текст и сохранённые исходные байты; binary/Base64 увеличивает размер локального хранения.

Кнопка **Request log** в верхней панели показывает последние 50 обменов текущей сессии, включая Runner и получение OAuth токена: подготовленный URL/headers/body, статус или ошибку, конечный URL и время до headers/скачивания body. Desktop также показывает переходы redirect. Authorization, cookies и headers с именами token/secret/key скрыты по умолчанию; переключатель **Show sensitive headers** раскрывает их. URL и body показываются без маскирования. Текст body ограничен 100 KiB, для бинарного body указан размер. Автоматические transport headers и промежуточные browser redirect ответы недоступны. Журнал очищается при перезапуске и не входит в backup.

## cURL и JSON-редактор

**Import cURL** над URL: вставьте команду, выберите коллекцию, проверьте preview и сохраните запрос. Поддерживаются распространённые флаги URL, method, headers, raw/JSON/urlencoded body, текстовые form fields, Basic Auth, Cookie, redirects и timeout. Неизвестные флаги отклоняются. Команды не выполняются, shell-переменные не раскрываются, локальные файлы по @path не читаются. Добавьте файлы через Body.

**Copy as cURL** использует текущий черновик и подставленные значения переменных/auth. Команда использует POSIX quoting; для файлов указывает имена, рядом с которыми должны быть доступные файлы. Значения credentials попадают в команду.

В **Body → JSON** доступны Format JSON, подсветка, проверка ошибок и Show resolved body. Переменные сохраняются как шаблоны при форматировании, включая числовые значения без кавычек: `{"id":{{userId}}}`. В URL и JSON ввод `{{` открывает автодополнение: стрелки, Enter/Tab или выбор мышью. Resolved URL показывает URL с подставленными query-параметрами.

## Переменные из ответа

Кнопка **Save value to environment** сохраняет JSON path или header текущего ответа в активное окружение. Вкладка **Capture** хранит автоматические правила запроса: source, path и variable. Например, `access_token → token`, затем Bearer `{{token}}` в следующем запросе.

Автоматические правила применяются только к 2xx ответам при выбранном окружении. Если хотя бы одно правило не удалось, значения не записываются. В Runner обновлённые переменные сразу доступны следующему запросу; результаты правил отображаются рядом с assertions. Изменения Capture требуют Save request для запуска сохранённого запроса в Runner.

## Резервные копии и настройки

**Workspace → Backup**: Download workspace backup или Show backup JSON. Копия включает коллекции, saved requests, open drafts, environments, cookies, историю, корзину, сценарии Runner и тему, а также вложения. По умолчанию известные credentials и отмеченные Secret значения исключаются; для их переноса включите **Include secrets**. Правила и ограничения экспорта описаны выше.

Restore проверяет формат, версию, уникальность ID, ссылки, поля и cookie fields, показывает preview и заменяет workspace. Лимит JSON backup — 50 MiB. В desktop сначала создаётся автоматическая копия текущего workspace, затем восстановление фиксируется одной транзакцией SQLite; интерфейс обновляется после успешной записи. В browser mode workspace, drafts и theme сохраняются одним setItem; при ошибке quota прежние данные сохраняются.

**App settings → Local storage** в desktop показывает до 10 автоматических копий. При обычных изменениях снимок создаётся не чаще раза в минуту; восстановление вручную всегда сохраняет предыдущее состояние независимо от этого интервала. **Preview backup → Restore automatic backup** позволяет проверить содержимое перед заменой. Эти копии находятся на том же ПК и не заменяют отдельный JSON backup для переноса.

При закрытии desktop-окна Reqmas ждёт завершения очереди сохранения. Если запись не удалась, окно остаётся открытым с сообщением и возможностью повторить сохранение; можно выгрузить JSON backup текущих данных.

**Settings** у запроса: timeout 0.1–300 секунд и Follow redirects. Они действуют также в Runner. Отключение redirect с просмотром первого 3xx ответа доступно в desktop; browser mode требует Follow redirects из-за ограничений Fetch/CORS.

**Settings → Proxy & TLS** доступны в desktop: HTTP/HTTPS proxy с username/password, доверенные CA в PEM и mTLS с цепочкой клиентских сертификатов и незашифрованным приватным ключом PKCS#8 или RSA в PEM. Дополнительные CA расширяют стандартное хранилище доверия; проверка сертификатов остаётся включённой. Поддерживаются переменные `{{proxyUrl}}` и другие шаблоны. Настройки действуют на отправленный запрос и получение OAuth токена, а сохранённые — также в Runner. Browser mode не отправляет запросы с сохранёнными connection settings; кнопка **Clear connection settings** удаляет их.

## Подписанные обновления

В desktop **App settings → Updates** принимает адрес HTTPS manifest и доверенный публичный ключ Tauri updater. После сохранения доступны **Check for updates**, просмотр версии и release notes, затем подтверждение установки. Подпись должна содержать ту же версию, что manifest; скачивание установщика ограничено 100 MiB. Перед установкой Reqmas сохраняет workspace.

Адрес сервера и ключ пока не настроены; с пустыми полями проверки выключены. Развёртывание хостинга и выпуск подписанного установщика выполняются отдельно: [UPDATES.md](../UPDATES.md). Приватный ключ не входит в исходники или архив переноса. Настройки сервера обновлений на новом ПК нужно указать отдельно.

## Локальная проверка

Локальный тестовый API для проверки вручную: `node tests/helpers/api-server.mjs` (http://127.0.0.1:58808). POST `/token` возвращает демонстрационный token; GET `/me` проверяет Bearer `demo-token`; `/echo`, `/slow` и `/redirect` помогают проверить body, таймаут и redirects. Данные синтетические.

Для новых возможностей импортируйте `tests/fixtures/reqmas-openapi.yaml`: `/items?caseId=1` проходит схему, `/bad-item` возвращает ошибки типов и required, `/download` выдаёт бинарный файл, `/image` — PNG. Для Runner замените значение параметра caseId на `{{caseId}}`, сохраните запрос, выберите только Get item и вставьте CSV `caseId` с двумя строками `1` и `2`.
