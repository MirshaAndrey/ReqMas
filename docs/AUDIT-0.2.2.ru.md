## Исправленные ошибки

- Закрытие окна: Tauri завершает обработчик close-request командой `destroy`, но capability разрешала только `close`. Теперь разрешён `destroy` для main-окна и используется после завершения очереди сохранения. Ошибки команды попадают в видимое сообщение, окно остаётся редактируемым и поддерживает повторную попытку. Регрессионные тесты связывают обработчик с реальным capability и проверяют порядок save → destroy, а также сбой/повтор.
- Состояние SQLite загружается и валидируется до первого рендера. Ошибка чтения или миграции блокирует запуск вместо записи пустого workspace. Старые localStorage-записи удаляются только после успешного durable save. Записи, настройки, вкладки и восстановление сериализованы; restore не меняет cache до успешной транзакции.
- Перенос saved request обновляет все соответствующие drafts без потери несохранённых полей. Перенос в корень использует нормализованное пустое значение и не создаёт ложное dirty-состояние. Неявные родители папок доступны в дереве и редакторе; специальные имена и глубокие пути не ломают навигацию.
- Горячие клавиши игнорируют открытые диалоги, составной ввод, повтор клавиш и занятые операции. Состояние сворачивания хранится в общем хранилище, поиск показывает скрытые совпадения без изменения сохранённого состояния.
- Runner сохраняет выбранный порядок и данные сценария. Retry повторяет только неуспешные выполненные задачи с исходными snapshot, iteration и dataset; успешные, отменённые и невыполненные задачи не повторяются. Устаревшие ссылки блокируют запуск до исправления сценария.
- Асинхронное чтение binary/multipart вложений не применяет поздний результат к другой вкладке. Отправка и смена вкладки заблокированы во время чтения, все чтения завершаются перед снятием busy.
- Browser и desktop ограничивают HTTP response body 100 MiB по объявленной длине и фактически прочитанным байтам. Предварительно отменённый reader больше не оставляет stream заблокированным, в том числе для пустого ответа.
- Результат OAuth сохраняется во вкладке, из которой началось получение, и в соответствующем saved request/collection. Refresh одного account сериализован, вращающийся refresh token сохраняется, отменённое ожидание завершается и устаревший token не возвращается после Clear. Поля аккаунта сбрасывают прежние credentials при изменении.
- Кнопка получения inherited OAuth token отображается только при активной OAuth-авторизации коллекции. PKCE-кнопка в browser mode отключена, включая наследуемую авторизацию.
- Защищённый экспорт не изменяет оригиналы: исключает marked secrets, структурированные credentials, cookies, proxy password/private key и известные sensitive headers/fields. OAuth token response в истории тоже очищается с сохранением точности чисел. Capture сохраняет Secret-флаг существующей переменной.
- Новые OAuth, connection settings и Secret-флаги валидируются в backup и сохраняются в Reqmas metadata Postman round trip. Некорректная необязательная metadata игнорируется с предупреждением.
- Исправлены цвета и ширина полей App settings в обеих темах. Проверены отсутствие переполнения документа при 700×600 и блокировка Ctrl+Enter внутри диалога.

Browser UI использовал синтетический API `http://127.0.0.1:58808`; пользовательские внешние API не вызывались. После тестов в browser preview возвращена исходная полная резервная копия. Интерфейс показал прежние 3 коллекции, 8 запросов, Development environment, Get a user draft и Dark theme. Ниже перечислены исправления этого аудита и проверенное поведение ранее добавленных функций. Документированные ограничения не учитывались как баги.

## Запросы, вкладки и локальные данные

- Исправлена синхронизация query-параметров со строкой URL в обе стороны. Повторяющиеся ключи, Unicode, включение/выключение и удаление строк сохраняют нужные значения без дублирования при отправке.
- Отмена не превращается в повторную отправку через submit формы. Поздний ответ после отмены не публикуется как успешный ответ.
- Ручная отмена и истечение timeout показывают разные сообщения. Поздний таймер не меняет причину уже выполненной отмены; в UI отдельно проверены Cancel и timeout 0,1 секунды.
- Результаты отправки и OAuth возвращаются во вкладку, из которой начался запрос; переключение вкладок не подменяет её response или draft.
- Ранний desktop cancel, поступивший до регистрации запроса в Rust, больше не теряется. В Runner отмена и таймаут завершают текущий шаг даже при игнорировании AbortSignal исполнителем; отменяются задержки, выполняется cleanup и блокируется повторный запуск.
- Восстановление workspace, drafts и theme стало атомарным: ошибка quota не оставляет частично восстановленные данные. Повреждённый основной документ хранилища не блокирует восстановление исправных legacy-записей.
- Переименование/удаление вложенных папок корректно применяется к saved requests и drafts, включая несколько последовательных изменений. Имена `constructor`, `__proto__` и `toString` обрабатываются как обычные пути.
- Асинхронное чтение файлов импортов защищено от поздних результатов: предыдущий файл не заменяет более новый выбор и не применяется после смены действия. Размер проверяется до чтения; file input сбрасывается для повторного выбора того же файла.
- Windows EXE использует GUI subsystem и в debug, и в release, чтобы при обычном запуске не появлялась консоль.

## Response, байты и журнал

- Pretty, Tree, Compare, Copy, Capture и JSON path assertions сохраняют точные большие ID и десятичные значения. Разные значения `9007199254740993` и `9007199254740992` больше не сливаются из-за округления JavaScript Number.
- JSON-форматирование request body и schema сохраняет исходные числовые токены, `-0` и шаблоны переменных без округления.
- Tree получил страницы: поля после 1000-го узла доступны для просмотра. При смене ответа сбрасывается устаревшая страница.
- Поиск не работает по невидимому placeholder бинарного ответа. Усечённый history snapshot не выдаётся за полноценный JSON или файл.
- Сохранение Response использует исходные байты. BOM, Windows-1251 и UTF-16 учитываются при отображении текста; скачивание сохраняет исходную кодировку.
- Повторные response headers не теряются. Set-Cookie сохраняются отдельно для cookie jar. Явный пустой Cookie header имеет приоритет над jar.
- Журнал хранит независимый снимок подготовленного запроса и результата; изменение исходных объектов не меняет старую запись. `X-Key` и другие credential headers скрыты до включения Show sensitive headers.
- Лимит redirect приведён к десяти переходам, без прежней ошибки на единицу. В журнале доступны desktop redirect hops, final URL и время получения headers/body.
- Бюджет истории расходуется на реально сохранённые данные: отброшенные большие бинарные payload не вытесняют старые текстовые body при свободном бюджете.

## Импорт и экспорт

- cURL `-G` сохраняет query из исходного URL и добавляет новые значения, включая одинаковые ключи. Несколько `--json` правильно конкатенируются без form-разделителя `&`.
- cURL quoting сохраняет буквальный backslash с переводом строки внутри одинарных кавычек. `--data-urlencode` не кодирует повторно уже закодированное имя параметра. Для выбора body editor используется последний Content-Type.
- Неподдерживаемый GET/HEAD body и несовместимое сочетание `-G` с multipart отклоняются с объяснением вместо тихой потери данных.
- cURL export использует `--head` для HEAD и сохраняет стандартные redirect semantics POST с body. Пустой multipart экспортируется с исходным boundary-only body.
- OpenAPI form-body сохраняет поля из явного example, дополнительные поля, повторяющиеся значения массива и свойства/required из `allOf`.
- OpenAPI response schema не требует request-only `writeOnly` поля. Рекурсивные локальные ссылки перенесены в самостоятельные `$defs`; имена свойств и literal JSON не повреждаются преобразованием схемы.
- Некорректный embedded base64 Postman не принимается как рабочее вложение. Для исправных embedded files убраны ложные требования повторного прикрепления.
- Некорректный строковый header Postman пропускает конкретный запрос и сохраняет остальные поддержанные запросы коллекции.
- Postman collection ограничена 50 MiB, 10 000 запросами и папками суммарно и 100 уровнями папок. Итеративный preflight проверяет ограничения до рекурсивного импорта. Environment ограничен 1 MiB и 10 000 переменными; некорректные записи и вложенные значения отклоняются явно.

## Schema, Runner, backup и auth

- JSON Schema защищена от подмены внутренних ссылок. При значениях, которые невозможно проверить без потери точности JavaScript Number, проверка явно завершается ошибкой; округлённое значение не выдаётся за прошедшее контракт.
- JSON datasets сохраняют точные числовые значения, включая большие ID, дроби, экспоненты и `-0`. CSV сохраняет quoted commas, doubled quotes, CRLF, multiline cells и пустые значения.
- Runner выполняет snapshot выбранных saved requests и collection/auth; environment и cookies обновляются между запросами намеренно, чтобы работали Capture и последовательные сценарии.
- Backup проверяет уникальность внутренних ID редакторов, историю и безопасные cookie fields. Повторение request ID в history/drafts допускается, поскольку это снимки одного запроса.
- Некорректный Max-Age корректно уступает Expires. Переполнение expiry ограничено; unsafe cookie names/values/control characters не попадают в headers. Поддерживаются нормализованные IPv6 hosts.
- OAuth lifetime `0` означает немедленное истечение. Очень большая lifetime остаётся конечной и сериализуемой, некорректные значения не создают invalid expiresAt.

## Границы и оставшиеся ограничения

- Это функциональный аудит текущей реализации, а не доказательство отсутствия всех багов, нагрузочное тестирование или отдельный security penetration test.
- Production frontend собирается с JS bundle около 506 kB (154 kB gzip). Vite сообщает предупреждение о размере; разделение загрузки редакторов и импортов можно сделать отдельной оптимизацией.
- Не проверялись production API сторонних сервисов, все разновидности proxy/TLS/mTLS, installer/update pipeline, cloud sync и платформы, отличные от текущей Windows-сборки.
- В browser mode сохраняются Fetch/CORS ограничения: недоступны некоторые headers, Set-Cookie и подробная цепочка redirects. Cookies промежуточных redirect-ответов пока не сохраняются.
- LocalStorage не является зашифрованным vault; действуют quota. Backup/export/cURL могут содержать credentials. Текущий полный ответ находится во вкладке; history ограничена 100 записями, 100 KiB на снимок и 1 MiB совокупно.
- Tree/форматирование имеют лимит JSON 2 MB и глубины; Tree показывает до 1000 узлов на странице. Diff ограничен 200 изменениями и 10 000 JSON узлами, с уведомлением об усечении.
- JSON Schema поддерживает draft-07 и 2020-12, локальные ссылки и конечные числовые значения без потери точности. Remote refs, dynamic refs/anchors и mixed dialects отклоняются. Точное отображение и перенос больших JSON чисел не означают, что schema validator может точно выполнить над ними все числовые проверки.
- OpenAPI требует самостоятельный документ с локальными `$ref`; выбирается один поддержанный server/media/security вариант. Сложная сериализация, OAuth flows, callbacks/webhooks и прикрепление внешних файлов требуют ручной настройки.
- cURL импорт разбирает поддержанный набор флагов как текст; shell commands/variables не исполняются, `@path` не читается. Postman scripts не выполняются.
- Client Credentials реализован; OAuth refresh, Authorization Code/PKCE и OAuth 1.0 остаются вне текущего функционала.

Пользовательские данные после ручных сценариев восстановлены. Файлы тестовых API, fixtures и regression tests остаются в `tests/` для повторения проверки.
